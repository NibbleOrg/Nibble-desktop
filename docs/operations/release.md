# macOS 发布与运维

Status: Current
Owner: 项目维护者
Last verified: 2026-11-13 — v1 规划契约；生产实现与实机行为未验证

## Resolution — macOS v1 发布、更新与质量门禁

维护者通过本票的逐轮讨论确认以下完整契约，最后一轮全部采纳。本决议取代此前错误的“暂缓发布规划”安排；规划无需等待本地体验或业务实现。这里只确定发布蓝图，不代表产物已经构建或测试已经通过。

### 发布定位与支持范围

- 首个公开版本为 **Preview**，通过公开 GitHub Releases 分发。功能仍在迭代，转为稳定版须在实际使用验证后另行决定。
- 实现阶段优先得到本地可整体启动的应用，体验 Workbench / Quick Panel 后再逐步设计复杂业务；这一顺序不是完成发布规划的前置依赖。
- 首期仅 Apple Silicon，最低 **macOS 14**。Intel 延后，Windows 不在首次发布内。
- 每次发布验证 macOS 14 和当时最新正式版；中间每个大版本至少验证安装、启动与更新。必需验证缺失则不发布，不以框架支持代替产品验证。

### 安装产物与信任边界

- 每个 Release 提供 Apple Silicon `.dmg` 安装包、更新器使用的 `.app.tar.gz` 与对应 `.sig`、SHA-256 校验文件、变更说明及安装指引。
- 应用采用 ad-hoc 签名，无 Apple Developer ID、无 Apple 公证。它不提供 Apple 开发者身份背书，不能消除 Gatekeeper 摩擦。
- 安装说明解释首次打开可能被阻止：先尝试打开，再到 System Settings → Privacy & Security → Open Anyway 按系统提示放行。受管理设备可能禁止例外，不承诺所有设备都能安装；不要求关闭系统整体安全防护。
- SHA-256 用于核对下载文件完整性；它不能代替更新器签名或 Apple 身份认证。

### 更新行为与签名运维

- 应用运行时每隔 **1 小时**自动检查更新；发现新版提示用户，不静默安装、不强制更新。
- 用户点击更新后下载并校验；完成后由用户点击 **“重启并更新”**。具体界面文案与布局留给实现，不改变两次用户触发的行为。
- 下载或签名校验失败继续使用当前版本。安装失败必须保留或恢复可运行旧版；这是需要发布前验证的恢复目标，不能只假定框架能保证。
- 更新包使用独立更新签名密钥，客户端内置公钥。私钥仅存于发布 secrets 与维护者安全备份中，不进入仓库、安装包或日志；签名校验不可省略。
- 更新入口指向已通过发布门禁的 Preview 版本；不能因 GitHub 的默认 latest 行为而遗漏 Preview。具体更新元数据生成方式属于实现细节。
- 更新签名私钥丢失可能切断现有客户端正常更新；任何轮换都必须验证客户端信任衔接，否则不得将新签名包直接投给旧客户端。

### 回滚与本地数据兼容

- 更新后发生产品问题时，撤下有问题的更新入口；用户可从 Releases 手动下载并重装旧版。不自动降级，不要求通过篡改版本号推送旧程序。
- 本地历史沿用[定义本地数据、剪贴板隐私与保留策略](https://github.com/NibbleOrg/Nibble-desktop/issues/7)的可丢弃数据原则，不新增备份、导入导出或数据迁移功能。
- 新旧版本遇到不兼容数据格式时，明确告知用户，经确认后重建；不得静默清空。未确认时不得继续执行破坏性重建。

### 诊断与隐私

- 不自动上传崩溃或使用数据。
- 仅提供用户主动导出、可预览的诊断包，由用户决定是否附到问题报告；排除剪贴板正文、Base64 输入输出及其他用户内容。不引入默认远程诊断依赖。

### 质量门禁与发布清单

所有 PR 必须通过格式检查、lint、类型检查、单元测试与构建。遵守[定义 Nibble Agent 与工程治理契约](https://github.com/NibbleOrg/Nibble-desktop/issues/4)的边界合同/集成验证要求。

每次发布由维护者确认：

1. 版本号、Preview 标识与变更说明正确。
2. 必需自动化检查通过，支持系统矩阵完成验证。
3. 验证安装与首次 Gatekeeper 放行、应用启动、Workbench / Quick Panel、全局快捷键和剪贴板权限行为。
4. 验证从上一已发布版本更新成功，以及下载失败、签名校验失败、安装失败的旧版保留/恢复路径；验证手动回装和不兼容数据确认流程。首次发布没有上一版本时明确注明，并用测试版本验证更新链路。
5. 安装包、更新包、独立签名、SHA-256 文件齐全并与本次版本一致；从实际下载路径核对产物。
6. Release 附安装指引、系统与架构要求、未公证说明、已知问题及回装说明。
7. 全部就绪后才开放本次更新入口。必需检查失败或未执行时不发布；未执行项如实标为 not verified，不等同通过。
