## Resolution — Windows v4 支持承诺与演进路径

维护者通过逐轮讨论并最终整体确认以下决议。本票完成版本承诺与架构演进边界；不代表 Windows 已实现、已验证，或所有 v4 发布选择均已确定。

### 版本与支持范围
- **v4 规划支持 Windows**，暂不绑定发布日期。完成实机兼容验证及发布门禁后才公开宣称支持；若无法通过，须显式调整版本计划。
- 初始目标为 **Windows 11 x64**；Windows 10 和原生 ARM64 暂不纳入支持承诺。具体最低系统版本在 v4 实施前根据届时依赖与验证结果确定。
- 已确定的 v1 功能和隐私规则作为 Windows 基线：Workbench 为 Calendar Home 与 Settings，Quick Panel 提供 Clipboard History 与 Base64；保留、删除、临时状态及隐私规则一致。v2～v4 新增能力的 Windows 适用范围由后续规划补充。

### 架构、平台交互与视觉
- v1 遵守 #8 的平台隔离契约，避免共享规则依赖 macOS API 或路径假设；Windows 原生适配、构建产物和实机验证安排在 v4。未来新增平台能力继续遵守此边界。
- 保持可配置全局快捷键唤起同一个 Quick Panel，关闭后尝试恢复原应用焦点。Windows 可使用不同默认组合，实机验证后确定；快捷键注册失败明确报告。
- 焦点恢复受系统限制时，不通过模拟粘贴或索取无关权限弥补。系统托盘、权限提示和窗口行为允许平台适配；不得静默削弱核心或隐私规则，无法解决的差异须显式讨论并记录。
- 保留布局层级、Quick Panel 白系与 Workbench 深色方向、键盘操作及减少动态效果行为。透明、模糊与窗口装饰允许不同实现；系统效果不可用时提供清晰可读的实色回退，不要求逐像素一致。

### 数据与迁移
- macOS 转 Windows 按全新安装与重新配置处理，不迁移剪贴板历史、密钥或设置，不提供跨平台同步。安装指引明确数据不会随平台或设备转移。
- 本票中的迁移路径指应用架构与平台交付的演进，不新增 #7 已排除的备份、导入导出和数据迁移功能。

### 分发、更新与签名
- 使用公开 GitHub Releases，初次 Windows 发布提供一种标准安装包；安装器类型在 v4 实施选择。便携版和 Microsoft Store 暂不纳入承诺。
- 验证安装、卸载、升级和手动回装，本地数据处理遵循已确定规则。
- 沿用 #10 更新契约：运行时每小时检查，用户触发下载与校验，再点击重启并更新；不强制或静默安装。失败保留或恢复可运行旧版，支持手动回装。
- Windows 更新包也必须独立签名；安装机制由 Windows 适配实现。
- 安装包与应用代码签名的方式、证书成本和维护方案在 v4 发布前单独确认。当前不承诺受信任发布者身份或无系统安全提示。发布前明确实际签名状态、安装指引及限制。代码签名与更新包签名分别决策。

### 验证与延后决策
- v4 发布前在届时明确的最低支持版本和最新正式版验证安装、卸载、启动、更新、回装、双界面、全局快捷键、焦点、剪贴板排除标记、安全存储和不兼容数据确认重建。
- 必需检查缺失或失败时不发布；自动化通过不能替代实机验证，不以能启动就宣称受支持。
- 以下事项明确延后，必须在 v4 实施或发布前形成可追踪任务并完成决策：具体最低 Windows 版本、安装器、代码签名方案、默认快捷键、v4 新增能力兼容矩阵。不得将这些事项解释为已经决定。

以上完成 #12 的规划范围，Windows 实施及发布验证属于后续 v4 工作。
